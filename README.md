# Moodle MMCS

Скилл + небольшой консольный клиент для Moodle мехмата ЮФУ (edu.mmcs.sfedu.ru): читать Moodle из AI-агента без управления браузером.
Подходит для Codex и других агентов с поддержкой папок `SKILL.md` и запуска Python.
Можно использовать клиент отдельно. Python **3.10 или новее**; основной API-режим без зависимостей.

## Подключить один раз

Скачайте эту папку. Откройте в ней терминал и выполните:

```sh
python3 scripts/moodle.py setup
```

На macOS можно вместо команды открыть `Connect.command` из этой папки.
На Windows используйте `py -3` вместо `python3`; если база временных зон отсутствует:
`py -3 -m pip install tzdata`.

Введите обычный **логин Moodle** и пароль. Пароль вводится скрыто, отправляется по HTTPS
непосредственно вашему Moodle и не сохраняется. Клиент сам получает токен мобильного сервиса,
проверяет его и сохраняет в `~/.config/moodle-mmcs/config.json` (на Unix права `600`).
Это локальный файл с токеном, а не шифрованное хранилище. На Windows он находится в вашем
пользовательском профиле; доступ определяется правами каталога Windows.

Готово: следующие обращения используют токен. Не нужно вручную искать токен в DevTools,
экспортировать HAR, держать вкладку открытой или повторять вход при каждом запросе.
Токен может быть отозван или иметь срок действия — тогда повторите `setup`.

На **edu.mmcs.sfedu.ru проверено 14.09.2026**: сервер сообщает `enablewebservices=1`,
`enablemobilewebservice=1`, `typeoflogin=1`, техническое обслуживание выключено.
Это подтверждает доступность стандартного способа подключения; окончательная проверка
прав конкретного пользователя происходит при `setup`.

Если токен у вас уже есть:

```sh
python3 scripts/moodle.py setup --token
```

Вставьте его в скрытый запрос терминала. Передавать токен аргументом командной строки не нужно.
Для автоматизированного окружения поддерживаются `MOODLE_TOKEN` и `MOODLE_URL`, предоставленные
через ваше хранилище секретов. Не включайте токен, конфигурацию или HAR в GitHub.

## Подключить к агенту

Скопируйте **папку целиком**, включая `scripts`, в каталог скиллов агента.
Для Codex это `~/.codex/skills/moodle-mmcs/`. Если папка уже существует, обновите файлы скилла;
конфигурация с токеном лежит отдельно и сохраняется. Откройте новую задачу, если агент ещё
не видит установленный скилл. Специальный MCP-сервер не требуется.

Можно попросить агента: «Установи скилл из этой локальной папки». После подключения пишите:

- «Используй $moodle-mmcs. Что нужно сделать на этой и следующей неделе?»
- «Покажи события следующей недели».
- «Прочитай это задание целиком: https://edu.mmcs.sfedu.ru/mod/assign/view.php?id=22163».
- «Найди предмет “Искусственный интеллект” и прочитай все разделы и материалы».
- «Покажи задания без срока и со старыми датами».

Каждый пользователь запускает `setup` у себя: общая папка скилла не содержит чужой учётной записи.

## Команды

```sh
python3 scripts/moodle.py doctor
python3 scripts/moodle.py courses
python3 scripts/moodle.py events
python3 scripts/moodle.py events --next-week
python3 scripts/moodle.py events --from 2026-09-15 --to 2026-09-30
python3 scripts/moodle.py events --course GD
python3 scripts/moodle.py read 'https://edu.mmcs.sfedu.ru/mod/assign/view.php?id=22163'
python3 scripts/moodle.py course 'Искусственный интеллект' --full
python3 scripts/moodle.py --output course-context.json course 'Искусственный интеллект' --full
python3 scripts/moodle.py file 'https://your-moodle.example/webservice/pluginfile.php/...' --dest lecture.pdf
```

Вывод — JSON с полными исходными полями, текстовыми версиями HTML и датами с часовым поясом.
`--output` стоит перед командой и сохраняет полный ответ, чтобы агент мог читать большой курс
по частям. Существующие файлы выгрузок и вложений не перезаписываются.

`events` по умолчанию проверяет текущую и следующую календарные недели (понедельник–воскресенье),
а не ближайшие 14 суток. `--to` включителен. По умолчанию Europe/Moscow.
Кроме календаря проверяются задания, тесты и другие типы со стандартными сроками;
отдельно возвращаются бессрочные, старые даты и прочие материалы, где требования могут быть в тексте.

`course` без `--full` — структура и описания. С `--full` — детали модулей, состояние сдачи,
форумы с пагинацией, глоссарии, базы данных, вики, HTML/текстовые материалы и реестр файлов.
PDF, DOCX, изображения, видео и внешние страницы агент читает отдельными средствами;
сам клиент не распознаёт бинарные документы и не запускает интерактивные задания.
Нестандартные плагины могут предоставить только описание/файлы. Непрочитанные детали
отмечаются в `issues`, а не выдаются за отсутствующие.

## Другой Moodle или несколько аккаунтов

```sh
python3 scripts/moodle.py --config /path/to/private/other.json setup --site https://moodle.example.edu
python3 scripts/moodle.py --config /path/to/private/other.json events --next-week
```

Можно задавать `MOODLE_CONFIG` вместо флага. Не используйте одну конфигурацию для разных аккаунтов.
Секрет отправляется только на настроенный HTTPS-сайт; перенаправления запросов с секретами
блокируются. На сервере с SSO/MFA прямой парольный вход может быть недоступен.
Если Moodle позволяет получить ключ в меню профиля → «Настройки» → «Ключи безопасности»,
можно использовать его через `setup --token`. Наличие этого пункта зависит от прав.
Для обычного входа через мобильный сервис отдельная выдача токена администратором обычно не нужна,
но клиент не может включить отключённый API или обойти ограничения аккаунта.

## Если нужен только календарь

В Moodle: «Календарь → Экспорт календаря → Все события → подходящий период → Получить URL календаря».
Выбирайте диапазон, покрывающий нужные даты. Затем:

```sh
python3 -m pip install 'icalendar>=6,<7' 'recurring-ical-events>=3,<4'
python3 scripts/moodle.py setup --ical
python3 scripts/moodle.py ical --next-week
```

Ссылка вставляется скрыто и сохраняется локально. Это альтернативный **ограниченный режим**,
не полный доступ к Moodle. В нём нет заданий без даты, состояния сдачи и материалов, которых
нет в DESCRIPTION. Для обычного API-режима библиотеки iCal не нужны.
`setup --ical` заменяет текущую конфигурацию; для параллельного использования задайте отдельный `--config`.
Локальные ICS можно читать через `ical --file /path/calendar.ics` вообще без подключения.

## Проверка и ограничения

`doctor` без подключения проверяет публичные настройки; после подключения также проверяет
токен, список курсов и доступные функции. Код завершения `0` — команда выполнена, `2` — ошибка,
`130` — отмена. Частичная выдача может иметь код `0`: агент обязан учитывать `issues` и `coverage`.

В комплекте есть офлайн-проверки дат, личных продлений, ID, файлов, пагинации и обработки ошибок:

```sh
python3 -m unittest discover -s tests -v
```

У сервиса мобильного приложения могут быть также права записи. Сам клиент использует
фиксированный список операций чтения, не отправляет работы и не начинает попытки тестов.
Подключение создаёт/получает токен обычным способом Moodle. «Полное содержимое» относится
к доступным аккаунту данным и поддерживаемым API, а не к скрытым заданиям и настройкам преподавателя.

Исходные HAR мехмата использованы для проверки маршрутов, но не включены в пакет. Данные старого снимка
не считаются актуальным состоянием Moodle. Без токена конкретного пользователя невозможно
заявлять о проверенном живом чтении его заданий.
